# DEV-NOTES-STT-WHISPER-LOCAL — локальные грабли проекта

_Обновлено: 2026-09-09_

Специфика: **локальный Whisper (faster-whisper / CTranslate2) + захват микрофона на этом ПК.**
Универсальные принципы из этой же истории живут в общем `DEV-NOTES.md` (разделы 18–22);
здесь — только проектное. Канонический экземпляр — в репозитории `STT-WHISPER-LOCAL`;
копий по другим папкам не держать (см. «Как расширять» в `DEV-NOTES.md`).

**Пометки машин:** `[ПК1: RTX 3050]` / `[ПК2: RTX 4060]` — факт расходится по машинам.
Без пометки — общее для проекта на обоих ПК (свойство софт-стека, не железа).

---

## 1. GPU-движок: cuBLAS не в сборке CTranslate2

- whisper-local 0.18.3 несёт в своём `ctranslate2\` только `cudnn64_9.dll`, но **не**
  `cublas64_12.dll`. Модель грузится, а первый `encode` бросает «`cublas64_12.dll is not
  found`»; GUI-обёртка ошибку **проглатывает** и виснет на «transcribing» (GPU-util 0 %,
  VRAM занят — счёт не начался).
- Лечение: `pip install nvidia-cublas-cu12 nvidia-cuda-runtime-cu12`, затем **скопировать**
  в `...\site-packages\ctranslate2\` файлы `cublas64_12.dll`, `cublasLt64_12.dll`,
  `cudart64_12.dll` (CT2 ищет DLL только рядом с собой). **Один `pip` без копирования не помогает.**

## 2. Использовать то окружение, где прошёл прямой тест

- cuBLAS «виден» только там, где DLL уже разложены. Прямой тест `faster_whisper` и GUI часто
  живут в **разных** venv / разных папках `ctranslate2` — отсюда «движок напрямую 0.14 с, а
  обёртка виснет». Свой скрипт запускать в том же venv, где прямой прогон дал результат.

## 3. CUDA mismatch «found 6.5»

- **`[ПК1: RTX 3050]`** — установщик сообщал «found 6.5, requires 12». Причина не версия CUDA,
  а старый `cudart64_65.dll` из `...\PhysX\Common` в системном PATH.
- **`[ПК2: RTX 4060]`** — PATH был чист, этой грабли нет; не переносить вывод с ПК1 на ПК2.
- Полный CUDA Toolkit (~3 ГБ) **не нужен**: драйвер даёт runtime CUDA 12+; локальные CUDA-12
  DLL в `ctranslate2\` перекрывают старый PhysX-DLL. Потолок рантайма — строка «CUDA Version»
  в `nvidia-smi`.

## 4. Модель — в одном выделенном потоке

- `WhisperModel` загружать и вызывать в **одном** выделенном потоке через очередь, не из
  callback хоткея. CT2-контекст привязан к потоку создания; вызов из чужого потока способен подвесить.

## 5. STT галлюцинирует на тишине — это сигнатура, не баг

- На тишине движок выдаёт фразы-заполнители: «Продолжение следует…», «Субтитры сделал…»,
  англ. «Thanks for watching». **Есть в выводе — значит на вход пришла тишина, а не голос**
  (искать в захвате/хоткее, не в модели). См. общий п.18.

## 6. Диагностика захвата микрофона на Windows

- Отдельная проба: записать N секунд → напечатать `peak`/`RMS`. Отделяет «микрофон молчит»
  от «хоткей рвёт запись» от «движок врёт». Логировать **уровень**, а не только «успех».
- **Устройство записи — машино-специфично** (периферия, не GPU): `[ПК2: Logitech B525]`,
  сильный сигнал `peak` ~0.175–0.25. На ПК1 своё устройство — сверять по своему `peak`,
  а не по числам ПК2.
- Windows может отдавать приложению цифровую **тишину без ошибки**. При `peak ≈ 0` проверить:
  Параметры → Конфиденциальность → Микрофон → доступ классическим приложениям; снять
  монопольный режим в свойствах устройства записи.

## 7. Хоткеи в whisper-local / библиотеке global_hotkeys

- Свойство **библиотеки** (софт, не железо — одинаково на обоих ПК). Надёжны: **буквы,
  `space`, F-клавиши, модификаторы** `ctrl`/`alt`/`shift`/`win`.
- Ломаются: **правый Alt / `AltGr`** и **символьные** клавиши (`/`, `.`, `,`) — слой
  нормализации их теряет, ключ становится пустым `[]` → краш на старте.
- Хоткеи применяются **только после перезапуска** приложения.
- Рабочая схема эталона — **конфиг** (`user_settings.yaml`, пер-машинный, не в репо):
  запись `ctrl+space`, стоп `f8`. Почему тумблер на зажатой клавише хрупок — общий п.19.

## 8. Вставка распознанного текста

- Кириллицу вставлять **через буфер обмена + эмуляция Ctrl+V**, не посимвольным вводом —
  надёжнее и не зависит от раскладки.
